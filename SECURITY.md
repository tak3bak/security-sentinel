---
## Reporting a Vulnerability
We take the security of our platform seriously. If you discover or suspect a security vulnerability, please report it responsibly as detailed below.
> **Note:** Please **do not** report security vulnerabilities through public GitHub issues, discussions, or pull requests.
### Preferred Reporting Method
* **GitHub Security Advisory:** Submit a private report directly via the **[GitHub Security Advisory Tab](../../security/advisories/new)** on this repository.
* **Direct Email:** Alternatively, email your disclosure to **security@nomadik.site**.
---
## What to Include in Your Report
To help us triage and investigate the issue efficiently, please include as much detail as possible:
* **Vulnerability Type:** (e.g., Remote Code Execution, Authentication Bypass, Broken Access Control, SQLi)
* **Affected Component / Endpoint:** Precise module, path, or API endpoint where the issue resides.
* **Steps to Reproduce:** Clear, step-by-step instructions or a minimal Proof of Concept (PoC).
* **Impact:** Potential security consequence if exploited in a production context.
* **Suggested Fix:** (Optional) Any recommendations or patches you may have identified.
---
## Response & Disclosure Process
1. **Acknowledgement:** We will acknowledge receipt of your report within **24–48 hours**.
2. **Triage & Assessment:** Our engineering team will validate and rate the severity of the report.
3. **Remediation:** If confirmed, we will develop and test a fix. We aim to release security patches within **14 business days** for high/critical severity issues.
4. **Public Disclosure:** Once a patch is released, a security advisory will be published crediting the reporter (unless anonymity is requested).
---
## Safe Harbor Policy
Any activities conducted in good faith, in accordance with responsible disclosure practices and local laws, will be considered authorized. We will not pursue legal action against security researchers acting in good faith.* **Steps to Reproduce:** A clear, step-by-step description to demonstrate the issue.
* **Impact:** A summary of how the vulnerability could be exploited and the potential impact on the system.

### What to expect
Once a report is submitted, the core security team will:
1. **Acknowledge** receipt of the report within 48 hours.
2. **Triage** the issue to determine its severity and validity.
3. **Collaborate** with the reporter on a fix and a timeline for public disclosure (if applicable).

We request that you do not publicly disclose the vulnerability until the team has had reasonable time to investigate and patch the issue.
